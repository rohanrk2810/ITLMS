# 20 - Class delivery options (built-in, Jitsi, external link)

A scheduled online class can run in one of three ways. The choice is made per session, in **Batch -> Schedule session -> How will this class run?**.

| Option | What the student sees | Attendance / monitoring / recording / questions |
|---|---|---|
| **Built-in live room** (default) | LiveKit room inside the LMS | Yes - all of it |
| **Jitsi** | Jitsi video inside the LMS page (iframe) | No |
| **Google Meet / Zoom link** | "Open meeting" page, link opens in a new tab | No |

## Why Google Meet cannot be embedded

Google Meet, Zoom and Teams send headers that stop browsers loading them in an iframe, and Meet's embed SDK is only for Workspace add-ons. A link that opens in a new tab is the most any LMS can do. Jitsi is built to be embedded, which is why it is offered as the "stays on our site" alternative.

## How it works

No schema change: the session's existing `meeting_url` column (batch-service) carries the choice.

- No link -> built-in LiveKit room, exactly as before.
- Link on the configured Jitsi host -> embedded in the room page. The room link is generated by the frontend as `https://<jitsi host>/itilms-<random 32 hex>`; the unguessable name is the only thing keeping outsiders out of a public Jitsi server.
- Any other http(s) link -> shown on an "Open meeting" page.

### Backend

- `ScheduleServiceImpl` accepts `meetingUrl` on create/update and rejects anything that is not an `http(s)` URL with a host. A link is dropped for OFFLINE sessions.
- `LiveClassServiceImpl.join` still runs the role, enrolment and join-window checks first. Only then, if the session has a link, it returns `JoinTokenResponse.external(...)` - no LiveKit room is created, no token minted, `serverUrl`/`token` are null, and `externalUrl` is set. A student who is not in the batch never receives the link.
- `BatchClient.SessionDetail` gained `meetingUrl`.

### Frontend

- `lib/jitsi.ts` - provider type, room-link generator, `isJitsiUrl`, `jitsiEmbedUrl` (fills the display name, skips the pre-join screen).
- `live-class-room-page.tsx` - renders the LiveKit room, the Jitsi iframe, or the external-link page depending on the join response. The LiveKit room has a **Full screen** button in its top bar (for trainer and students): the class is laid over the whole window, and the browser's fullscreen is requested on top where it allows it; Esc leaves.
- `VITE_JITSI_HOST` (default `meet.jit.si`) points at your own Jitsi server.

## Limits

- Classes on Jitsi or an external link get **no automatic attendance**, monitoring, recording or live questions. Mark attendance manually.
- On the public `meet.jit.si`, anyone who learns the room link can join, and Jitsi may limit embedded use. For private, reliable classes run your own Jitsi server and set `VITE_JITSI_HOST`.
- "Generate schedule" does not copy a link onto the sessions it creates; set the option when scheduling a single session.
- There is no edit form for an existing session's link yet (the update endpoint supports it).
